\### Задание 1. Распознавание элементов



\* \*\*Начало или конец\*\* (Овал / скругленный прямоугольник)

&#x20; \* \*Назначение:\* показывает точку входа и выхода алгоритма.

&#x20; \* \*Пример:\* Начало; Конец.

\* \*\*Действие (процесс)\*\* (Прямоугольник)

&#x20; \* \*Назначение:\* вычисление, присваивание значения.

&#x20; \* \*Пример:\* S ← a + b.

\* \*\*Ввод или вывод\*\* (Параллелограмм)

&#x20; \* \*Назначение:\* получение исходных данных, выдача результата.

&#x20; \* \*Пример:\* Ввод a, b; Вывод S.

\* \*\*Условие (решение)\*\* (Ромб)

&#x20; \* \*Назначение:\* проверка условия, два выхода "Да"/"Нет".

&#x20; \* \*Пример:\* a > b?

\* \*\*Линия потока\*\* (Линия со стрелкой)

&#x20; \* \*Назначение:\* показывает порядок перехода между блоками.

&#x20; \* \*Пример:\* переход к следующему блоку.

\* \*\*Соединитель\*\* (Небольшой круг с меткой)

&#x20; \* \*Назначение:\* связывает части схемы без длинных линий.

&#x20; \* \*Пример:\* A ... A (пара одинаковых меток).

\### Задание 2. Чтение линейной блок-схемы



\* \*\*Какую задачу решает:\*\* Алгоритм находит площадь (S) и периметр (P) прямоугольника по двум заданным сторонам (a и b).

\* \*\*Величины:\*\* 

&#x20; \* Входные: `a`, `b`.

&#x20; \* Выходные: `S`, `P`.

&#x20; \* Промежуточных величин в данном алгоритме нет.

\* \*\*Ограничения на данные:\*\* Стороны прямоугольника должны быть строго положительными числами (a > 0, b > 0).



\#### Трассировка при a = 4, b = 7:



| Шаг | Выполненный блок | Значения после действия | Переход |

| :--- | :--- | :--- | :--- |

| 1 | Ввод a, b | a = 4; b = 7; S = -; P = - | К вычислению S |

| 2 | S ← a · b | a = 4; b = 7; S = 28; P = - | К вычислению P |

| 3 | P ← 2 · (a + b) | a = 4; b = 7; S = 28; P = 22 | К выводу |

| 4 | Вывод S, P | a = 4; b = 7; S = 28; P = 22 | К завершению |

| 2 | S ← a · b | a = 2.5; b = 6; S = 15; P = - | К вычислению P |

\### Задание 3. Чтение ветвления



\* \*\*Назначение:\*\* Алгоритм находит наибольшее (максимальное) из двух чисел `a` и `b` и записывает его в переменную `m`.

\* \*\*Ручная проверка для пар:\*\*

&#x20; \* \*\*Пара (9; 4):\*\* Условие 9 ≥ 4 — \*\*Да\*\*. Ветвь «Да» (m ← 9). Вывод: \*\*9\*\*.

&#x20; \* \*\*Пара (-3; 2):\*\* Условие -3 ≥ 2 — \*\*Нет\*\*. Ветвь «Нет» (m ← 2). Вывод: \*\*2\*\*.

&#x20; \* \*\*Пара (5; 5):\*\* Условие 5 ≥ 5 — \*\*Да\*\*. Ветвь «Да» (m ← 5). Вывод: \*\*5\*\*.

\* \*\*Замена a ≥ b на a > b:\*\* Конечный результат работы алгоритма \*\*не изменится\*\* (так как если числа равны, не имеет значения, какое из них присвоить в m). Однако для равных чисел \*\*изменится выбранная ветвь\*\*: при условии a ≥ b алгоритм пойдет по ветке «Да» (m ← a), а при условии a > b — по ветке «Нет» (m ← b).

\### Задание 4. Чтение цикла



\* \*\*Количество выполнений тела цикла при N=4:\*\* Тело цикла выполнится ровно \*\*4 раза\*\*.

\* \*\*Проверка при N=1 и N=0:\*\*

&#x20; \* \*\*При N=1:\*\* Условие i ≤ N (1 ≤ 1) выполнится 1 раз, тело отработает, S=1, на следующем шаге 2 ≤ 1 — Ложь. Вывод: \*\*S = 1\*\*.

&#x20; \* \*\*При N=0:\*\* Условие i ≤ N (1 ≤ 0) сразу станет ложным («Нет»). Тело цикла не выполнится ни разу. Вывод: \*\*S = 0\*\*.

\* \*\*Назначение начальных значений:\*\* `S ← 0` — зануление сумматора (накопителя суммы), чтобы к нему можно было корректно прибавлять элементы. `i ← 1` — установка начального значения счётчика (начинаем суммирование с единицы).

\* \*\*Почему цикл завершается:\*\* Так как N ≥ 0 является фиксированным числом, а на каждом шаге цикла переменная i увеличивается на 1 (i ← i + 1), значение i рано или поздно станет строго больше N. Условие i ≤ N вернет «Нет», и цикл завершится.



\#### Трассировка при N=4:



| Шаг | Выполненный блок | Значения переменных | Результат условия / переход |

| :--- | :--- | :--- | :--- |

| 1 | Ввод N | N = 4; S = -; i = - | К инициализации S |

| 2 | S ← 0 | N = 4; S = 0; i = - | К инициализации i |

| 3 | i ← 1 | N = 4; S = 0; i = 1 | К проверке условия |

| 4 | Проверка i ≤ N | N = 4; S = 0; i = 1 | 1 ≤ 4? \*\*Да\*\* (1-й проход) |

| 5 | S ← S + i | N = 4; S = 1; i = 1 | К изменению счётчика |

| 6 | i ← i + 1 | N = 4; S = 1; i = 2 | К проверке условия |

| 7 | Проверка i ≤ N | N = 4; S = 1; i = 2 | 2 ≤ 4? \*\*Да\*\* (2-й проход) |

| 8 | S ← S + i | N = 4; S = 3; i = 2 | К изменению счётчика |

| 9 | i ← i + 1 | N = 4; S = 3; i = 3 | К проверке условия |

| 10 | Проверка i ≤ N | N = 4; S = 3; i = 3 | 3 ≤ 4? \*\*Да\*\* (3-й проход) |

| 11 | S ← S + i | N = 4; S = 6; i = 3 | К изменению счётчика |

| 12 | i ← i + 1 | N = 4; S = 6; i = 4 | К проверке условия |

| 13 | Проверка i ≤ N | N = 4; S = 6; i = 4 | 4 ≤ 4? \*\*Да\*\* (4-й проход) |

| 14 | S ← S + i | N = 4; S = 10; i = 4 | К изменению счётчика |

| 15 | i ← i + 1 | N = 4; S = 10; i = 5 | К проверке условия |

| 16 | Проверка i ≤ N | N = 4; S = 10; i = 5 | 5 ≤ 4? \*\*Нет\*\* (Выход) |

| 17 | Вывод S | N = 4; S = 10; i = 5 | К завершению |

\### Задание 5. Поиск и исправление ошибок



\* \*\*Случай A:\*\*

&#x20; \* \*Ошибка:\* Нарушены графические стандарты блоков ввода и вычисления, пропущена линия потока.

&#x20; \* \*Последствия:\* схему невозможно однозначно прочитать; нарушена логическая связность (алгоритм "застревает" после шага P).

&#x20; \* \*Исправление:\* заменить прямоугольник ввода на параллелограмм, параллелограмм вычислений на прямоугольник, провести стрелку от P ← 2 · (a + b) к Вывод S, P. (Исправленная схема совпадает со схемой из Задания 2).

\* \*\*Случай B:\*\*

&#x20; \* \*Ошибка:\* перепутаны ветви «Да» и «Нет» после условия.

&#x20; \* \*Последствия:\* алгоритм вместо большего числа будет находить меньшее (минимум).

&#x20; \* \*Исправление:\* поменять местами блоки действий на ветках, либо изменить условие на противоположное. (Исправленная схема совпадает с Заданием 3).

\* \*\*Случай C:\*\*

&#x20; \* \*Ошибка:\* отсутствует инкремент счётчика (i ← i + 1).

&#x20; \* \*Последствия при N = 3:\* значение i всегда останется равным 1. Условие 1 ≤ 3 всегда истинно. Возникает бесконечный цикл, программа зависнет.

&#x20; \* \*Последствия при N = 0:\* условие 1 ≤ 0 сразу ложно. Цикл завершится корректно, выведет 0.

&#x20; \* \*Таблица зацикливания (первые 3 прохода для N=3):\*

&#x20;   \* Шаг 4: 1 ≤ 3 (Да) → S = 1.

&#x20;   \* Шаг 7: 1 ≤ 3 (Да) → S = 2.

&#x20;   \* Шаг 10: 1 ≤ 3 (Да) → S = 3. Значение i не меняется.

\* \*\*Случай D:\*\*

&#x20; \* \*Ошибка:\* не задано начальное значение накопителя суммы S.

&#x20; \* \*Последствия:\* на первом же шаге цикла операция S ← S + i попытается использовать неопределенное значение переменной S. Это приведет к критической ошибке исполнения (обращение к неопределенной памяти).
